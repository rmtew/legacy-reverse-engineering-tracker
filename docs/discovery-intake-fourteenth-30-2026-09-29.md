# Fourteenth discovery intake: next 30 leads

The prior batch left nine open leads. Collected GitHub repository search results with `fork:false`, reconciled them against the catalogue, then enriched the 45 eligible results with repository descriptions before fixing this next ranked slice. Without descriptions, title-only ranking put a different, weaker order first. The nine older leads remain queued; this fixed top 30 comprises new, higher-ranked repository URLs. Inspected metadata, root file lists, READMEs and selected assembly/source. Build, hardware and byte comparisons were not independently rerun.

**Result:** 27 projects, two duplicate/mirror decisions and one exclusion. All 30 URLs leave the queue; 24 other leads remain. This pass includes BBC/Acorn and Spectrum work, a C64 cartridge study, and a specifically MSX disassembly surfaced by a Spectrum search.

## Programmatic observations

| Observation | Applied technique or next improvement | Boundary |
| --- | --- | --- |
| A general C64 disassembly search returned 100 results dominated by `c64rom` and `c64ref` forks; the otherwise identical `fork:false` search returned 11. | Added `fork:false` to every saved repository query. Existing local screening still checks results, but now the limited first page has room for independent projects. | GitHub's fork flag is incomplete lineage evidence: unmarked copies and independently valuable forks still need bounded comparison or explicit links. Code searches and known-source traversal are unaffected. |
| Search adapter results lacked descriptions, so the cheap relevance score ranked title keywords above old leads and ignored actual scope. | Enriched eligible repositories with primary description metadata before freezing the batch. The automated REST collector already receives descriptions; external adapters should normalize to the same hit shape before ranking. | A description is a routing hint, not qualification. README and selected files still determined the decisions. |
| A Spectrum query surfaced an MSX-specific project because the MSX loader imitates Spectrum tape behavior. | Assign platform from analyzed tape/binary rather than query, title keywords or historical ancestor. A classifier could flag mismatches for human review. | Do not suppress mismatches at search time; Stardust is substantive work. |
| Two same-owner repositories served only as site pointers or duplicate generated output. | A cheap root inventory plus cross-repository blob SHA comparison can suggest mirrors before full review; the Cruising index content matched exactly. | One matching HTML file cannot alone prove whole-repository equivalence; the surrounding README and content were checked. |
| “Disassembly” covered ROM glyph data, bare labels, commented assembly, translated C++ and byte-checked source. | Extract concrete artifact types, build checks and cited predecessors into separate candidate signals instead of one keyword score. | Exactness and playability remain upstream claims until reproduced. A bare listing can still be a distinct relevant artifact. |
| Two Chuckie Egg studies share selected comments but publish different analysis artifacts. | Mine explicit README credits and record directed attribution; screen for wholesale copy before collapsing a lineage. | Same title and overlapping annotations do not by themselves make the later disassembly a duplicate. |
