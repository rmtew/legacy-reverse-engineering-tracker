## Process observations and improvements

- Current README/sources.md already include substantial homebrew and native ports, but the older discovery guide still excluded ordinary ports broadly. This pass aligns the guide with the current scope and explicitly distinguishes creator releases from third-party ROM collections. No scope expansion is introduced.
- Homepage titles can hide significant implementations: HelloAmi contains library replacement and bootblocks; a documentation site preserves assembly.library sources. Inspect artifact inventories instead of classifying from names or stale agent guidance.
- Provenance dates and filenames can contradict summaries: Hägar has a 2001 programmer-source note versus a 2021 README claim; assembly.library contains a 41.22 version string versus a 41.21 badge. Keep such dates/version claims qualified.
- Proposed future intake improvement: classify README links as provenance/dependency/successor hints and flag ambiguous source-availability claims for human review. Do not automatically promote based on binaries, README wording or AI claims.
- Proposed future evidence improvement: report archive file inventories and exact build-tool versions as structured triage hints. Slotshot has source but a private compiler; Robot Jet Action pins KickC 0.82; these distinctions matter independently of project eligibility.
- All target/source CPU audits accompany new records. Architecture flags do not become minimum runnable hardware. No changes were made to scheduled refresh or cron workflows.
